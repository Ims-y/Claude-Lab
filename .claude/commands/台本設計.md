~/Brain/YouTube/patterns/ の全ファイルを読んで、「$ARGUMENTS」の台本構造を設計して。

## 前処理：Brain Vaultの読み込みと集計

`~/Brain/YouTube/patterns/` 内の全 `.md` ファイル（`deprecated/` 配下を除く）を読み込み、
以下を集計してから設計に入ること：

```
有効パターン一覧：
  フックタイプ別の記録本数を集計する
  例：
    2. 感情落差型：3本（確定採用）
    5. 無音ショック型：1本（仮説段階）
    7. ループ誘発型：2本（確定採用）
    …

採用可能なパターン（2本以上）：[リスト]
仮説段階のパターン（1本のみ）：[リスト]
```

## 参照ルール（n=1禁止）

- **ステータス：無効** のファイルは参照しない
- **ステータス：仮説中** のファイルは参照可能だが、使用時に「仮説段階」と明記すること
- 同一フックタイプが **2本以上** 記録されているもの → 確定採用可能
- **1本しかないパターン** → 「仮説段階」として明記し、今回の台本には採用しない
- 有効なパターンが1つもない場合（運用開始直後等）→ その旨を明記した上で「仮説段階として新パターンを試す」として進める

## 設計項目

### 1. 形式判定
以下を先に決め、理由を述べよ：
- **Shorts**（60秒以下）
- **ロング**（3分以上）

判断基準：テーマの感情強度・ストーリー複雑度・Brain Vaultの成功事例の形式分布

### 2. KPI目標（形式別）

**Shorts の場合：**
| KPI | 目標値 |
|---|---|
| 3秒保持率 | 80%以上 |
| ループ率 | 40%以上 |
| CTR（Shorts feed内） | 10%以上 |

**ロングの場合：**
| KPI | 目標値 |
|---|---|
| 30秒維持率 | 75%以上 |
| 平均視聴維持率 | 50%以上 |
| CTR | 8%以上 |

### 3. タイトル案（3パターン必須）

以下の3型を各1本ずつ提示する。キーワードよりも「クリックしたくなる」感情的引力を優先する。

- **驚き型**：予想外の事実や行動を前面に出す
- **共感型**：飼い主・動物好きが「これ私のことだ」と感じる
- **数字型**：数字・期間・回数が入る

各タイトルは日本語60字以内。AI・動物・感情のうち2要素以上を含めること。

### 4. サムネイル感情

以下4種から1つ選択し、**なぜその感情がCTRを上げるか**を述べよ：
`驚き / 喜び / 不安 / 共感`

Brain Vaultのthumbnail-formulas.mdが存在する場合は参照して根拠を補強すること。

### 5. フック設計（冒頭3秒）

確定採用パターン（2本以上記録済み）から1つを選び、以下を記述する：

```
使用フックタイプ：[番号 + パターン名]
採用根拠：[Brain Vaultの記録N本から]

冒頭3秒の設計：
  映像：[AIプロンプトに指示する具体的な映像内容]
  音声：[セリフ / SE / 無音 のどれか + 内容]
  感情の流れ：[例：驚き → 期待 → 笑い]
```

### 6. 構成（秒数/分数と内容）

形式に応じた構成を以下の粒度で記述する：

**Shorts（例）：**
```
0:00〜0:03  フック（上記設計）
0:03〜0:10  状況の深化（なぜこうなったかをビジュアルで示す）
0:10〜0:25  クライマックス（感情のピーク）
0:25〜0:30  余韻 / ループ誘発のエンディング
```

**ロング（例）：**
```
0:00〜0:30  フック + 約束の提示
0:30〜1:00  前提・背景（簡潔に）
1:00〜2:30  本編（3〜5ポイント構成）
2:30〜3:00  クライマックス + CTA
```

### 7. 離脱防止ポイント（3箇所）

構成の中で離脱が起きやすい時点を3か所特定し、各ポイントで仕掛けを設計する：

```
ポイント1（__秒）：[離脱リスクの理由] → [仕掛けの内容]
ポイント2（__秒）：[離脱リスクの理由] → [仕掛けの内容]
ポイント3（__秒）：[離脱リスクの理由] → [仕掛けの内容]
```

### 8. 仮説設定（必須）

この台本で検証する仮説を **1つだけ** 記載する。

```
仮説：「[具体的な条件] にすると [測定するKPI] が [目標値] を超える」
検証KPI：[3秒保持率 / CTR / ループ率 / 30秒維持率 から1つ]
判定日：公開 + 14日後
```

## 保存

設計完了後、`~/Brain/YouTube/scripts/[テーマ]_台本構造.md` に以下のフロントマターを付けて保存する：

```markdown
---
title: [動画タイトル（採用案）]
format: Shorts / 長尺
hook_type: [番号 + パターン名]
hypothesis: "[仮説の文章]"
test_metric: [検証するKPI]
verdict_date: YYYY-MM-DD（公開14日後に記入）
verdict: 未判定
ctr: —
retention_3s: —
retention_30s: —
avg_retention: —
loop_rate: —
published: —
---
```

保存完了後、「台本構造を保存しました：[ファイルパス]」と報告すること。
